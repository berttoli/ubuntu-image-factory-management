# Contributing

1. Make focused changes and update documentation/status with the implementation.
2. Never commit secrets, private keys, passwords, generated artifacts, or mutable release assets.
3. Run `make validate test` before opening a pull request. Run `make security` when changing build inputs, hardening, or container contents.
4. Use Conventional Commit-style messages (`feat:`, `fix:`, `ci:`, `docs:`, `test:`, `chore:`).
5. Add or update tests for configuration, naming, policy, or release behavior changes.
